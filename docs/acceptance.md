Framework evidence: [run 38690572356](https://github.com/techpool/textkeep/actions/runs/38690572356), commit `6432d5f`, passed all sixteen normal/staged checks and nine active process-termination recoveries on API 29, 36 and 37. These cover encrypted-journal recovery across process restart and interrupted AtomicFile replacement; a bound pending outbox across restart; acknowledgement racing with a newer revision; Unicode MMS codec; real Firebase Auth initialization with encrypted preferences; normal system SMS-role cancellation and acceptance; offline origin-bound OTP receipt/notification/copy; and recovery after a committed provider insert without its Room acknowledgement. The provider fixture preserves two distinct identical messages, remains stable on repeated replay and suppresses historical OTP alerts. Additional checks preserve a fresh OTP behind 100 failing MMS receipts, restore a backup-only AtomicFile journal, distinguish pre-existing identical provider rows, isolate archive bindings verify the configured notification timeout and mark only the opened conversation’s incoming rows as read. No role, permission or app-op override was used. These results do not establish every instruction-level crash boundary, physical carrier transport, PIN lock, Direct Boot or OEM reliability.

The initial workflow masked instrumentation failures through a shell pipeline; it now uses `pipefail` and retains diagnostics. The radio harness also starts instrumentation before SMS injection so instrumentation cannot kill the receiver mid-delivery. The passing run above includes both corrections.

Release 0.1.0 was withdrawn after a default-role lookup issue. Version 0.1.1 corrected the role lookup but failed Google sign-in because a Firebase preference wrapper was cast to `Application`. Version 0.1.2 uses the actual application context with encrypted preferences. The tester installed its same-key update on a physical phone and confirmed Google sign-in works.

The tester confirmed that ChatGPT connects successfully through deployed Google/OAuth consent after the continuation and CSRF fixes. The connected integration also returned sync status successfully. No actual message content was opened during verification.

The physical tester followed the normal default-SMS and offline synthetic-SMS checklist and reported that both inbox receipt and the Copy code notification work on the installed release. This is physical SMS/clipboard evidence; phone OS version was not supplied, and it does not establish carrier MMS, PIN lock, Direct Boot, dual-SIM or Doze behavior.

The connected TextKeep integration successfully invoked `get_sync_status`; the ISO last-sync timestamp was verified after fixing Date serialization. A real PostgreSQL regression asserts the exact timestamp survives the SDK response. The corrected source passed server/contracts tests with no database skips, TypeScript checks and production build. Two web rendering regressions also verify that HTML/scripts/links remain inert text, preserving Unicode and newlines.

After the refresh correction, the actual ChatGPT connection returned sync status after all previously issued access tokens expired. It returned status again after its original authorization-server browser session expired; runtime metadata confirmed token rotation. No message content was read.

## Remaining physical-device checklist

These remain NOT TESTED unless a narrower result above explicitly records otherwise:

- Carrier MMS send, receive, download and image display; multipart/Unicode outgoing SMS, failed/delivery callbacks, short codes, alphanumeric senders and dual-SIM routing.
- PIN-locked Copy code, duplicate/stale alert behavior under device lock, reboot with an incoming SMS before first unlock, and replay after unlock.
- Role loss/reselection and runtime permission revocation on the actual phone; local behavior during Firebase/backend outages, expired sign-in and Google sign-out.
- Doze, battery saver and manufacturer background limits with measured delays; manufacturer backup/device-transfer behavior.
- Installing the latest release over the existing app while retaining messages, keys, consent, account and registration; debug-package Google sign-in on a test device.

A tester confirmed offline incoming SMS and Copy code on a physical release, but could not test MMS. No connected USB device was available. Keep the release experimental until the remaining carrier and device gates are verified.
