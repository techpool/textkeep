Framework evidence: [run 38680708825](https://github.com/techpool/textkeep/actions/runs/38680708825), commit `79b2b3e`, passed all eleven staged checks on API 36 and 37. These cover encrypted-journal recovery across process restart and interrupted AtomicFile replacement; a bound pending outbox across restart; acknowledgement racing with a newer revision; Unicode MMS codec; real Firebase Auth initialization with encrypted preferences; normal system SMS-role cancellation and acceptance; offline origin-bound OTP receipt/notification/copy; and recovery after a committed provider insert without its Room acknowledgement. The provider fixture preserves two distinct identical messages, remains stable on repeated replay and suppresses historical OTP alerts. No role, permission or app-op override was used. These results do not establish every instruction-level crash boundary, physical carrier transport, PIN lock, Direct Boot or OEM reliability.

The initial workflow masked instrumentation failures through a shell pipeline; it now uses `pipefail` and retains diagnostics. The radio harness also starts instrumentation before SMS injection so instrumentation cannot kill the receiver mid-delivery. The passing run above includes both corrections.

Release 0.1.0 was withdrawn after a default-role lookup issue. Version 0.1.1 corrected the role lookup but failed Google sign-in because a Firebase preference wrapper was cast to `Application`. Version 0.1.2 uses the actual application context with encrypted preferences. The tester installed its same-key update on a physical phone and confirmed Google sign-in works.

The tester confirmed that ChatGPT connects successfully through deployed Google/OAuth consent after the continuation and CSRF fixes. The connected integration also returned sync status successfully. No actual message content was opened during verification.

The physical tester followed the normal default-SMS and offline synthetic-SMS checklist and reported that both inbox receipt and the Copy code notification work on the installed release. This is physical SMS/clipboard evidence; phone OS version was not supplied, and it does not establish carrier MMS, PIN lock, Direct Boot, dual-SIM or Doze behavior.

The connected TextKeep integration successfully invoked `get_sync_status`; the ISO last-sync timestamp was verified after fixing Date serialization. A real PostgreSQL regression asserts the exact timestamp survives the SDK response. The corrected source passed all eight server/contracts tests with no database skips, TypeScript checks and production build.
